Natalia Kosovarova · AI Automation PortfolioExample 1 · Design Export

Updating Solution Design on the Low-Code Platform and Exporting It to Confluence

Challenge

Solution design was maintained on a low-code configuration server, but the built-in export did not work. For more than a year, documentation had been prepared manually and gradually drifted from the actual configuration.

Solution

The first tool compared Confluence documentation with objects on the low-code platform and highlighted discrepancies. After an analyst approved the changes, the tool automatically updated the corresponding object descriptions. Once developers configured the export templates, a second tool transferred documentation from the internal Confluence instance to the external one.

Outcome

Both workflows were implemented and tested: updating object descriptions on the low-code platform and transferring documentation to the external Confluence instance.

Migrating Solution Design from Sparx Enterprise Architect to Confluence

Challenge

Solution design was stored in Sparx Enterprise Architect, which no longer met the needs of developers and testers. Migrating it to Confluence required diagrams to be redrawn manually and notes, linked documents, and complex tables with merged cells to be converted.

Solution

The tool converts diagrams into editable draw.io format, transfers notes, linked documents, and tables with merged cells, and generates ready-to-use Confluence pages.

Outcome

The tool was handed over to analysts for day-to-day use and to engineers for support and further development.

Natalia Kosovarova · AI Automation PortfolioMethod

Principles for Developing Automation Tools

01

Use Case Selection

Priority is given to simple, repetitive tasks carried out by many people.

02

Algorithm First

Clear rules are implemented as algorithms. An AI model is used only where interpretation is required.

03

Data Stays Inside

Customer data is not sent to external AI services. Only code, not customer data, is used during development.

04

Cross-Validation

Code generated with Claude Code is checked with OpenAI Codex and then reviewed manually.

05

No Additional Access

Tools operate only with the access rights already assigned to the user.

06

Ownership and Evolution

Each tool and shared skill has a designated owner. Any team member can propose changes through Git. The owner reviews and approves changes. Shared skills are managed separately from tool code.

Personal Project: Telegram Assistant with an Open Architecture

What It Is

An agentic system in Telegram for managing tasks and reminders, monitoring email, and tracking habits.

Changes via Chat

The same Telegram chat can be used to request changes to the assistant itself. Claude Code turns the request into a code change, applies it, and restarts the assistant. The new capability becomes available in the chat immediately.

Architecture

The assistant is deployed on a VPS and uses the Anthropic API. Agents are separated by role and permissions, secrets are stored in a secrets manager, and data is kept in an encrypted SQLite database. Irreversible actions require explicit confirmation in Telegram.
